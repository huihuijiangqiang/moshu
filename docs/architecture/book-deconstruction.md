# 拆书分析边界

![书稿拆解为章节、人物、地点与时间线](../assets/moshu-deconstruction.png)

![拆书分析页面](../assets/screenshots/deconstruct.png)

## 目标

拆书是 P1 的参考学习功能：用户上传一份自己有权使用的作品，查看章节结构、节奏节点、爽点分布和每章摘要。它不修改当前作品，也不把参考稿写入设定库、正文、向量库或训练语料。

## 数据生命周期

1. 前端以受限的原始字节流提交单个 TXT、Markdown、DOCX 或 EPUB 文件，不使用可能落临时文件的 multipart 缓冲。
2. API 要求登录，在内存中逐块读取并分析，文件大小上限 10 MB。
3. DOCX/EPUB 只读取 ZIP 条目，不落地临时目录；压缩比、总展开大小、加密包和危险 XML 声明会被拒绝。
4. 响应只返回统计、章节摘要和启发式信号，不返回完整原文；请求结束后服务端不保存任何分析结果。
5. 前端刷新或清空后结果消失，当前作品数据不发生变化。

## 分析口径

MVP 不调用模型，不消耗作者积分。章节识别基于常见中文章节标题、`Chapter N`、序章/楔子/尾声/番外；无法识别时退回单个“全文”章节并标记低置信度。

节奏节点和爽点分布是可解释的启发式统计：对白符号、冲突/揭示/情绪/结果词汇和段落分布共同产生信号。结果必须带免责声明，不能被描述为版权审查、抄袭检测或文学质量评分。

## 运行边界

- 支持 UTF-8、UTF-8 BOM、GB18030 和 UTF-16 文本编码。
- 单文件超过 10 MB 或解码后超过 200 万字符时拒绝分析。
- 压缩文档展开总大小超过 50 MB、压缩比超过 100、加密或包含 `DOCTYPE/ENTITY` 时拒绝。
- 真实部署仍应在网关层补充按用户/账号的请求频率限制；本端点不把内存计数器当作多副本限流方案。

## 验收

- 未登录请求返回 401。
- 正常文本返回章节、节奏节点、十个百分位爽点桶和版权免责声明。
- 无章节标题的文本返回一个低置信度“全文”章节。
- GB18030 文本可读；未知扩展名、空文件、超大文件和恶意 XML 返回明确 422 错误码。
- 分析后数据库中不新增项目、章节、设定、生成运行或用量记录。
