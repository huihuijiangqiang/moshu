# 墨枢前端审阅报告

**审阅日期**: 2026-08-29  
**审阅范围**: 设计系统、Vue 3 组件实现、样式一致性、用户体验优化

---

## 执行摘要

前端代码质量整体良好，设计系统 **Modernist** 规范清晰，核心功能（TipTap 编辑器、AI 待采纳草稿、设定库引用）已实现。但存在以下可优化点：

1. **设计系统执行不一致** - 部分组件硬编码样式值，绕过设计令牌
2. **响应式能力缺失** - 固定宽度布局无法适配不同屏幕
3. **可访问性基础薄弱** - 缺少语义化 HTML 和键盘导航
4. **性能优化空间** - 虚拟滚动未实现，大作品会卡顿
5. **组件复用度低** - 重复样式逻辑未抽象为可复用组件

## 一、设计系统执行审查

### ✅ 做得好的地方

1. **令牌化完整**  
   `_ds/modernist-*/styles.css` 定义了完整的设计令牌体系：
   - 色彩：中性色 9 阶 + 强调色 9 阶，OKLCH 统一明度
   - 字体：Archivo 双档（heading 800 / body 400）
   - 间距：1-8 级对数刻度
   - 阴影：3 档高程

2. **CSS 变量一致性**  
   `app.css` 正确使用 `var(--color-*)` 引用令牌，未硬编码颜色值

3. **中英混排字体栈**  
   `--font-cjk: 'Archivo', 'PingFang SC', ...` 兼顾拉丁与 CJK 渲染

### ❌ 需要改进的地方

#### 1.1 内联样式滥用

**问题**：多处组件用 `:style` 硬编码尺寸和间距，绕过设计系统。

**案例** (`WorkspaceView.vue:76-77`)：
```vue
<button class="btn btn-secondary" :style="{ height: '30px', fontSize: '12px' }">
```

**影响**：
- 维护成本高（改尺寸要改 N 处）
- 无法统一调整设计规范
- 不响应主题切换

**建议**：
1. 抽象 `btn-sm` / `btn-xs` 尺寸变体到 `styles.css`：
```css
.btn-sm { height: 30px; font-size: 12px; padding: 0 12px; }
.btn-xs { height: 24px; font-size: 11px; padding: 0 8px; }
```

2. 替换内联样式：
```vue
<button class="btn btn-secondary btn-sm">
```

#### 1.2 魔术数字间距

**问题** (`WorkspaceView.vue:87`)：
```vue
:style="{ height: '42px', padding: '0 24px', fontSize: '12px', gap: '18px' }"
```

**建议**：用设计令牌替代：
```vue
:style="{ 
  height: '42px',  /* 可接受：特定模块高度 */
  padding: `0 var(--space-6)`,  /* 24px → --space-6 */
  fontSize: '12px', /* 可接受：界面文字固定尺寸 */
  gap: 'var(--space-4)'  /* 18px 接近 --space-4 (16px) */
}"
```

#### 1.3 颜色直接引用令牌变体

**问题** (`界面设计.dc.html:88`)：
```html
<div style="background: var(--color-accent); color: #fff;">
```

**建议**：避免硬编码 `#fff`，改用语义令牌：
```css
/* 在 app.css 定义 */
.active-item { 
  background: var(--color-accent); 
  color: var(--color-bg);  /* 浅色主题是白，深色主题会自动匹配 */
}
```

## 二、响应式与布局

### ❌ 当前问题

1. **固定宽度布局**  
   三栏宽度硬编码（`--app-left-w: 240px`, `--app-right-w: 320px`），小于 1280px 的屏幕会溢出。

2. **界面设计稿假定 1440×900**  
   但实际用户可能使用：
   - 13" MacBook Pro (2560×1600 @2x → 1280×800 逻辑分辨率)
   - 外接 4K 显示器 (3840×2160 @1.5x → 2560×1440)
   - Windows 笔记本 (1920×1080 → 实际可用 1800×920)

### ✅ 建议方案

#### 2.1 断点系统

在 `app.css` 添加：
```css
:root {
  --breakpoint-sm: 768px;
  --breakpoint-md: 1024px;
  --breakpoint-lg: 1280px;
  --breakpoint-xl: 1440px;
}
```

#### 2.2 弹性三栏布局

```css
/* 替换固定宽度 */
.app-body {
  display: grid;
  grid-template-columns: 
    minmax(200px, 240px)   /* 左栏：最小 200px，理想 240px */
    minmax(600px, 1fr)     /* 中栏：至少 600px，剩余空间自适应 */
    minmax(280px, 320px);  /* 右栏：最小 280px，理想 320px */
  gap: 0;
}

/* 小屏折叠侧栏 */
@media (max-width: 1280px) {
  .app-body {
    grid-template-columns: 200px 1fr 280px;
  }
}

@media (max-width: 1024px) {
  /* 左右栏变为抽屉，仅显示中栏 */
  .app-body {
    grid-template-columns: 1fr;
  }
  .pane-left, .pane-right {
    position: fixed;
    top: var(--app-header-h);
    bottom: 0;
    width: 280px;
    z-index: 30;
    transform: translateX(-100%);
    transition: transform 0.25s;
  }
  .pane-right {
    right: 0;
    transform: translateX(100%);
  }
  .pane-left.open { transform: translateX(0); }
  .pane-right.open { transform: translateX(0); }
}
```

#### 2.3 正文容器自适应

```css
.prose {
  max-width: min(var(--prose-w), 100% - 48px); /* 720px 或 容器宽度-边距 */
  margin: 0 auto;
  padding: 44px 24px 120px;
}
```

## 三、可访问性 (A11y)

### ❌ 当前缺失

1. **语义化 HTML 不足**  
   - 章节树用 `<div>` 而非 `<nav>` + `<ul>`
   - 按钮用 `<div class="btn">` 而非 `<button>`

2. **键盘导航缺失**  
   - 章节树无 `ArrowUp/Down` 导航
   - AI 工具条无 `Tab` 顺序

3. **屏幕阅读器支持为零**  
   - 无 `aria-label` / `aria-describedby`
   - 状态变化无 `aria-live` 通知

### ✅ 建议改进

#### 3.1 章节树语义化

**当前** (`ChapterSidebar.vue`):
```vue
<div class="side-item" @click="open(ch.id)">
```

**改进后**:
```vue
<nav aria-label="章节导航">
  <ul role="tree">
    <li role="treeitem" :aria-current="active === ch.id">
      <button @click="open(ch.id)" @keydown="handleNav">
        {{ ch.title }}
      </button>
    </li>
  </ul>
</nav>
```

#### 3.2 AI 生成状态通知

```vue
<div 
  v-if="generating" 
  role="status" 
  aria-live="polite" 
  aria-atomic="true"
>
  正在生成第 {{ words }} / {{ target }} 字
</div>
```

#### 3.3 守卫问题列表

```vue
<section aria-labelledby="guard-heading">
  <h3 id="guard-heading" class="kicker">守卫提醒 · {{ issues.length }}</h3>
  <ul role="list">
    <li 
      v-for="issue in issues" 
      :key="issue.id"
      :aria-describedby="`issue-${issue.id}-desc`"
    >
      <strong>{{ issue.title }}</strong>
      <p :id="`issue-${issue.id}-desc`">{{ issue.description }}</p>
    </li>
  </ul>
</section>
```

## 四、性能优化

### ❌ 当前瓶颈

1. **章节树无虚拟滚动**  
   80万字 ≈ 270章，DOM 节点 270+ 会拖慢渲染。规划文档要求："章节树超 200 项会卡，需要虚拟滚动"

2. **编辑器全量渲染**  
   3000字章节还好，但如果误操作粘贴 10万字会直接卡死

3. **自动保存节流不够激进**  
   当前 3秒节流，快速输入时仍会触发过多网络请求

### ✅ 优化方案

#### 4.1 虚拟滚动章节树

使用 `@vueuse/core` 的 `useVirtualList`（规划文档推荐）：

```vue
<script setup>
import { useVirtualList } from '@vueuse/core'
import { computed } from 'vue'

const { list, containerProps, wrapperProps } = useVirtualList(
  computed(() => store.chapters),
  { itemHeight: 36 }  // .side-item 高度
)
</script>

<template>
  <div v-bind="containerProps" style="height: calc(100vh - 200px); overflow: auto;">
    <div v-bind="wrapperProps">
      <div 
        v-for="{ data: ch, index } in list" 
        :key="ch.id" 
        class="side-item"
      >
        {{ ch.title }}
      </div>
    </div>
  </div>
</template>
```

#### 4.2 编辑器懒加载

TipTap 内容过长时分段渲染：

```ts
// use-novel-editor.ts
import { Editor } from '@tiptap/core'
import { Document } from '@tiptap/extension-document'

const CustomDocument = Document.extend({
  addOptions() {
    return {
      ...this.parent?.(),
      maxInitialRender: 5000  // 仅渲染前5000字，其余懒加载
    }
  }
})
```

#### 4.3 防抖自动保存

```ts
// use-autosave.ts
import { useDebounceFn } from '@vueuse/core'

const debouncedSave = useDebounceFn(async () => {
  await api.saveChapter(chapterId.value, html.value)
}, 5000, { maxWait: 10000 })  // 5秒防抖，最多10秒必存
```

## 五、组件复用与抽象

### ❌ 重复代码

1. **守卫问题卡片** - `AiPanel.vue` 和 `GuardView.vue` 重复实现
2. **设定条目卡片** - 三处用不同样式渲染同一数据
3. **空状态占位** - 每个视图自己写空状态

### ✅ 建议抽象

#### 5.1 创建 `GuardIssueCard.vue`

```vue
<template>
  <div 
    class="guard-card"
    :class="`guard-card--${severity}`"
    :style="{ borderLeftColor: severityColor }"
  >
    <strong>{{ title }}</strong>
    <p class="muted">{{ description }}</p>
    <div v-if="actions" class="guard-actions">
      <button 
        v-for="action in actions" 
        :key="action.key"
        class="chip"
        @click="$emit('action', action.key)"
      >
        {{ action.label }}
      </button>
    </div>
  </div>
</template>

<script setup lang="ts">
interface GuardIssue {
  title: string
  description: string
  severity: 'low' | 'medium' | 'high'
  actions?: Array<{ key: string; label: string }>
}

defineProps<GuardIssue>()
defineEmits<{ action: [key: string] }>()

const severityColor = computed(() => {
  switch (props.severity) {
    case 'high': return 'var(--color-accent)'
    case 'medium': return 'var(--color-accent-2)'
    default: return 'var(--color-neutral-500)'
  }
})
</script>

<style scoped>
.guard-card {
  border-left: 2px solid;
  padding-left: 12px;
  line-height: 1.6;
  margin-bottom: 12px;
}
.guard-actions {
  display: flex;
  gap: 8px;
  margin-top: 8px;
}
</style>
```

#### 5.2 创建 `EmptyState.vue`

```vue
<template>
  <div class="empty-state">
    <div class="empty-icon">{{ icon }}</div>
    <h3>{{ title }}</h3>
    <p class="muted">{{ description }}</p>
    <slot name="action" />
  </div>
</template>

<style scoped>
.empty-state {
  display: grid;
  place-items: center;
  text-align: center;
  padding: var(--space-8);
  min-height: 320px;
}
.empty-icon {
  font-size: 48px;
  opacity: 0.3;
  margin-bottom: var(--space-4);
}
</style>
```

使用：
```vue
<EmptyState

  icon="✓"

  description="系统未检测到设定冲突或伏笔超期"
```

## 六、用户体验细节优化

### 6.1 加载状态

**问题**：生成章节时无进度感知，用户不知道是卡了还是在跑。

**改进**：
```vue
<div v-if="generating" class="gen-progress">
  <div class="gen-bar">
    <div class="gen-fill" :style="{ width: `${progress}%` }" />
  </div>
  <span class="muted">{{ words }} / {{ target }} 字 · 预计还需 {{ eta }}s</span>
</div>
```

### 6.2 快捷键提示

**问题**：用户不知道 `Tab` 续写、`@` 引用等快捷键。

**改进**：在编辑器空状态加快捷键提示：
```vue
<div v-if="isEmpty" class="editor-hint">
  <p>按 <kbd>Tab</kbd> 让 AI 续写</p>
  <p>输入 <kbd>@</kbd> 引用设定库</p>
  <p>选中文字后按 <kbd>Cmd+K</kbd> 打开行内 AI</p>
</div>
```

样式：
```css
kbd {
  display: inline-block;
  padding: 2px 6px;
  font-size: 11px;
  font-family: ui-monospace, monospace;
  background: var(--color-neutral-200);
  border: 1px solid var(--color-divider);
  border-radius: 3px;
}
```

### 6.3 保存冲突处理

**问题**：规划文档要求"冲突时并列展示双方内容"，但前端只做了 409 检测，没有 UI。

**改进**：创建 `ConflictResolverModal.vue`：
```vue
<template>
  <div class="modal">
    <h2>保存冲突</h2>
    <p class="muted">服务端版本已更新，请选择保留哪一方：</p>
    <div class="conflict-diff">
      <div class="conflict-pane">
        <h3>你的版本</h3>
        <div v-html="clientHtml" />
        <button @click="resolve('client')">保留我的</button>
      </div>
      <div class="conflict-pane">
        <h3>服务端版本</h3>
        <div v-html="serverHtml" />
        <button @click="resolve('server')">保留服务端</button>
      </div>
    </div>
  </div>
</template>
```

## 十、总结

墨枢前端整体架构合理，设计系统 Modernist 执行到位，核心编辑器功能稳定。主要问题集中在：

1. **细节打磨不足** - 内联样式滥用、响应式缺失
2. **性能盲区** - 虚拟滚动未实现，大作品会卡
3. **可访问性为零** - 需补齐语义化与键盘导航

建议按 P0 → P1 → P2 顺序实施，预计 3 周可完成核心优化，第 4-6 周完成可访问性改造。优化后可显著提升产品专业度和用户体验，为工作室版多人协作打好基础。
