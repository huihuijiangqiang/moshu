产品定位：以 AI 代写为主的网文生产平台。一键成章是入场功能，一致性守卫与作者风格指纹是差异点，工作室产线是第二阶段的商业化放大器。

01  用户与场景

三类用户的核心矛盾不同，MVP 只优先满足前两类，第三类的数据结构要提前留好。

P0
全职日更作者

要的是速度，怕的是失控。日更压力下需要 AI 铺量，但绝不接受读者认出「AI 味」，也不接受写到后期人设崩坏。

关键任务
今天要交 3 章 → 从章纲生成初稿 → 按自己的风格改 → 确认无设定冲突 → 发布
P0
新人兼职作者

要的是「能开工」。不会搭框架、不懂黄金三章，需要产品把流程铺好，用模板引导他做出第一个可读的开头。

关键任务
一句灵感 → 选题材模板 → 生成设定与总纲 → 出前三章 → 看到「可以继续」的信号
P1 · 第二阶段
内容工作室

要的是产能可控。多个写手同时写一个 IP，需要共享设定、统一风格、可审稿、可看产量。付费能力最强。

MVP 需预留
组织 / 成员 / 角色权限三张表，作品归属于组织而非个人

02  功能需求

P0 = MVP 必须有；P1 = 第二阶段；P2 = 观察后再定。带 ★ 的是差异化功能，验收标准要写死。

优先级 模块 需求描述 验收标准
P0 项目与章节管理 作品 / 卷 / 章三级结构，拖拽排序，回收站，字数与日更统计。 80 万字作品打开首屏 < 2s；章节切换 < 200ms。
P0 写作编辑器 专注写作界面，自动保存，版本历史，离线草稿；选中文本唤起 AI 浮层（续写 / 扩写 / 润色 / 改写）。 断网后继续可写，恢复网络自动同步且不丢字；自动保存间隔 ≤ 3s。
P0 开书向导 灵感一句话 → 题材模板 → AI 生成设定 + 总纲 + 卷纲 → 生成前三章。每步可编辑后再进下一步。 新用户从注册到拿到第一章正文 < 5 分钟，中途可退出续做。
P0 一键成章 基于章纲 + 设定库 + 前情摘要生成整章正文，流式输出，可中断、可重生成、可只重写某段。 3000 字章节首字延迟 < 3s，全章 < 90s；重生成保留已锁定段落。
P0 设定库 人物 / 势力 / 地点 / 物品 / 力量体系 / 伏笔六类条目，支持关系与别名；正文中 @ 引用并高亮。 条目被引用时生成必然注入；条目改名后正文引用自动跟随。
P0 ★ 一致性守卫 每章保存后异步跑检查：新增设定自动抽取入库（待确认）、与既有设定冲突告警、未回收伏笔倒计时。 人工植入 20 处矛盾的测试稿中召回 ≥ 14 处，误报率 ≤ 20%。
P0 模型与额度 基础档国产模型无限量，高级模型按积分计费；用量面板显示本月消耗。 额度不足有明确提示与降档建议，不静默失败。
P0 导出 全量导出正文（TXT / DOCX / Markdown）+ 设定库 + 大纲，一键打包，无需付费。 导出内容可完整还原，定价页明确写出该承诺。
P1 ★ 作者风格指纹 上传本人 ≥ 5 万字旧作，抽取风格档（句长分布、对白占比、口头禅、意象偏好、章末钩子），生成时对齐并给偏离度评分。 盲测中作者本人认为「像我写的」比例 ≥ 60%。
P1 AI 占比自查 给出全章 AI 生成占比与「疑似 AI 句式」标注，辅助规避平台审查。 标注可逐句跳转，可一键重写。
P1 拆书 导入他人作品，输出节奏节点、爽点分布、章纲结构，供学习参考。 仅供参考不入库，避免侵权风险提示。
P1 ★ 工作室产线 组织共享设定库与风格档；主笔派章、写手领章、主编审稿留批注；产量看板。按席位计费。 同一作品 5 人并行不冲突；审稿意见可定位到段落。
P2 转剧本 / 短剧 小说转剧本格式、分镜。竞品已有，但非核心用户诉求。 观察工作室客户是否真实需要后再定。
P2 平台直投 对接平台投稿接口。依赖商务，不确定性高。 —

03  核心机制：分层记忆

这是整个产品的技术心脏。每次生成请求的上下文按固定预算装配，长度不随作品字数增长。

第 1 层 · 常驻
稳定设定

主角卡、金手指、力量体系、世界规则、风格档。整本书内极少变化。

预算 ~6k token
策略 全量 + prompt caching
第 2 层 · 检索
相关条目

本章章纲里出现的人物、地点、伏笔条目。走实体索引精确命中，向量检索兜底。

预算 ~5k token
策略 章纲实体抽取 → 索引查询
第 3 层 · 滚动
前情摘要

每章写完生成 200 字摘要；每 10 章压缩成卷级摘要。逐级压缩，长度恒定。

预算 ~4k token
策略 章摘要 + 卷摘要金字塔
第 4 层 · 原文
相邻上下文

前 2 章原文（尤其上一章结尾）。保证文气与场景连续，这层不能省。

预算 ~10k token
策略 定长截取，优先章末
设计约束

单次生成上下文硬上限 25k token。任何功能不得突破——突破了成本模型就崩了，而且长上下文并不会让输出更好，只会更贵更慢。

04  技术选型

前端按你的要求定为 Vue 3。选型原则：编辑器是唯一不能妥协的地方，其余一切从简。

前端
Vue 3.5 + TypeScript + Vite — 组合式 API，<script setup>
Pinia — 状态；作品/章节/设定库各一个 store
Vue Router — 编辑器路由用 keep-alive 保活
UnoCSS 或 Tailwind — 原子化，配合设计 token
TipTap 3（@tiptap/vue-3） — 编辑器核心，见下方说明
VueUse — 自动保存、快捷键、离线检测
Dexie（IndexedDB） — 离线草稿与断网续写
Element Plus — 仅后台/设置页，正文界面不用
编辑器为什么选 TipTap 而不是 wangEditor / Quill：AI 建议的「接受 / 拒绝 / 局部重写」需要在文档模型上叠加临时装饰层（decoration）与自定义节点，这是 ProseMirror 的强项。TipTap 是 headless 的 ProseMirror 封装，官方支持 Vue 3。@tiptap/suggestion 直接用来做 @ 引用设定条目。wangEditor 开箱快但扩展模型弱，做到「AI 段落作为可回退的节点」会很痛。
后端
Python + FastAPI（算法同学也在 Python 生态，一致性守卫与摘要链路省一次跨语言）。若团队更熟 Node，NestJS 同样成立。
PostgreSQL + pgvector — 关系数据与向量检索合并在一处，MVP 阶段不要引入独立向量库。
Redis + Celery / BullMQ — 摘要生成、一致性检查、风格抽取全部异步化，绝不阻塞写作。
SSE 而非 WebSocket — 生成是单向流，SSE 更简单且穿透代理更稳；协作阶段再上 WebSocket。
模型层
自建模型网关：统一 OpenAI 兼容协议，按任务路由（摘要用便宜模型、正文用主力模型、高级档可选顶级模型），失败自动降级，全量记录 token 与成本归因到用户。
必须支持 prompt caching——第 1 层设定常驻，这是成本模型成立的前提。
不做自研模型。MVP 阶段的差异化在上下文工程和产品逻辑，不在模型权重。
协作（P1）
Yjs + Hocuspocus — TipTap 官方协作方案，工作室阶段接入。
提醒：MVP 阶段不要提前引入 Yjs。它会改变整个持久化模型，在单人场景纯属负担。但数据库设计时把章节正文作为独立文档存储，为将来切换留出余地。

05  前端要提前解决的四个硬问题

这四个如果架构时没想，后期返工代价极大。

01
绝不把整本书装进一个文档

80 万字放进单个 ProseMirror 文档会直接卡死。一章一文档，章节列表只加载元数据（标题、字数、状态），正文按需拉取，切章卸载。左侧章节树超过 200 项时用虚拟滚动。

02
流式插入不能打断光标

SSE 逐块到达时，若直接 insertContent 会不断重置选区、污染撤销栈。做法：AI 输出先进独立的草稿节点（自定义 node，带 pending 标记，不进 history），用户点「采纳」时才作为一次事务合并进正文——撤销一次即可全部回退。

03
丢稿是不可原谅的

三层保险：本地 IndexedDB 每次变更即写、节流 3s 上传服务端、服务端保留最近 50 个版本快照。断网时顶部常驻提示并继续可写，恢复后按「本地较新则以本地为准，冲突则并列展示」处理，永不静默覆盖。

04
设定引用要活着

@ 引用存的是条目 id 而非文字（自定义 inline node，渲染时读当前名称）。这样改名自动跟随，且服务端能精确知道本章引用了哪些条目——一致性检查和上下文装配都依赖这份引用关系。

07  里程碑（10 周 MVP）

第 1-2 周
骨架

Vue 工程搭建、设计 token 落地、作品/章节 CRUD、TipTap 接入与自动保存。

第 3-4 周
设定库 + 网关

六类条目、@ 引用节点、模型网关与用量记账、SSE 通路打通。

第 5-6 周
生成链路

分层记忆装配、一键成章、草稿节点与采纳/拒绝、章摘要异步生成。

第 7-8 周
一致性守卫

设定抽取、冲突检测、伏笔追踪、报告界面。这是 MVP 的成败点，留足时间调准确率。

第 9-10 周
收口

开书向导、导出、额度与支付、离线容错、10 位种子作者内测。

明确不做（MVP）

  • 移动端完整编辑 —— 只做只读与速记
  • 多人实时协作 —— 数据结构预留，功能后置
  • 自研模型或微调 —— 差异化不在这里
  • 转剧本、漫剧、视频 —— 竞品的战场，不跟
  • 榜单选题数据 —— 拿不到同等数据源
  • 社区、作者交流 —— 无人运营等于负资产

待决议

  1. 一致性守卫的召回率指标是否现实 —— 需先做算法预研 spike，再定 MVP 承诺
  2. 基础档模型具体选哪家 —— 需实测中文网文语感，别只看榜单
  3. 后端语言 Python 还是 Node —— 取决于团队现有人手
  4. 是否 MVP 就上工作室席位版 —— 若已有明确付费客户，值得提前
